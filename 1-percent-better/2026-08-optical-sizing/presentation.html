Turning on optical sizing for Inter across APL

A look at what Inter's optical size axis does, why it's a low-risk, high-craft upgrade for our type system, and how we get there.

APL Design Tokens · Inter Variable, opsz 14–32 ·
01 — Concept

What is optical sizing?

Most typefaces ship one set of letterforms that gets mathematically scaled up or down. Inter instead redraws its letterforms across a size axis called opsz — small sizes get more open apertures and slightly looser spacing for legibility; large sizes get tighter spacing and more refined details, since legibility isn't the constraint anymore.

Inter's optical size axis

Inter's variable font defines this axis from 14 to 32. Below 14, the font is clamped to the 14 instance (its most "legible" shape set). Above 32, it's clamped to the 32 instance (its most "refined" shape set). There's no adaptation outside that range — a fact that turns out to matter a lot for how safely we can roll this out (see conclusion #1).

03 — Proposal

What we're proposing for APL

Turn on font-optical-sizing: auto globally across APL's Inter-based type styles. The browser (or, on native, our own opsz mapping) automatically picks the right letterform for each token's size — no per-token maintenance, no manual swapping between "text" and "display" cuts.

Why now

Inter is already APL's core sans typeface. Turning on its optical axis is additive — it doesn't require adopting a new typeface, changing sizes, or touching component APIs. It's a rendering-layer upgrade.

Why it's low-risk

Because the axis floor is 14, our smallest, most structurally load-bearing text (buttons, labels, table cells) is unaffected. The tokens that shift are headings, display type, and numbers — places width fluctuation is far less likely to break layout.

How this was explored

05 — Conclusions

What we found

1

Body text is unaffected

Every APL body/UI token sits at or below Inter's opsz floor of 14. Turning optical sizing on globally will not change letterforms or widths for metadata, extrasmall, small, compact, or paragraph styles — meaning buttons, form fields, table cells, and labels stay exactly as wide as they are today.

No layout risk
2

Headings benefit — tighter tracking, redrawn glyphs

Heading tokens (16–20px) sit just above the opsz floor, so they'll pick up Inter's optically-tightened spacing and refined letterforms. The shift is real but modest at this size — see the morph demo below at a dramatized 20px‑equivalent scale.

Watch fixed-width containers (16–20px)
3

Numbers benefit the most

Number tokens (32–48px) are the largest Inter sizes we use anywhere in APL, putting them closest to the opsz ceiling of 32 — the point of maximum optical refinement. This is where the craft upgrade will be most visible: AUM figures, returns, and other large numerics will render with Inter's most refined large-size shapes.

Biggest visible improvement
4

Remove the manual −1px letter-spacing on number tokens

That −1px tracking was added as a manual optical correction before Inter's optical sizing axis existed. Once optical sizing is on, its own built-in spacing adjustment does that job — stacking our manual −1px on top makes large numbers feel over-tightened. This adjustment should be removed as part of the rollout, not just left in place.

06 — Implementation

How we'll ship this

  1. 1

    Enable optical sizing at the theme level

    Add font-optical-sizing: auto to APL's base Inter font stack (wherever --theme-font-family-sans is applied), rather than per-component. This makes it a global, single-point toggle.

  2. 2

    Remove the number-token letter-spacing override

    Delete or zero out the −1px letter-spacing currently applied to number-l, number-xl, and number-xxl (via --theme-letter-spacing-number). Optical sizing supersedes this manual correction.

  3. 3

    Leave body/UI token letter-spacing untouched

    No change needed for metadata/extrasmall/small/compact/paragraph tokens — confirmed unaffected by the opsz floor, so their existing tracking values remain correct as-is.

  4. 4

    QA pass on the 16–20px "watch zone"

    Spot-check heading tokens in fixed-width UI (table header cells, tab labels, modal title bars) for wrapping or truncation regressions before merging — this is the one place a width shift is plausible.

  5. 5

    Browser/platform support check

    font-optical-sizing is supported in Chrome, Edge, and Safari. Confirm current support in any WebViews or older embedded browsers APL still targets; where unsupported, the fallback is simply today's default (no visual regression, just no benefit).

/* apl-theme.css — base sans font stack */
--theme-font-family-sans: 'Inter', 'Univers-Next', 'Helvetica Neue', 'Helvetica', 'Arial', 'sans-serif';

/* add globally alongside the font-family declaration */
font-optical-sizing: auto;

/* components.css — number tokens: remove this line */
letter-spacing: var(--theme-letter-spacing-number, -1px); /* ← delete */

What doesn't change

No token renames, no size changes, no component API changes. This ships as a rendering + one token cleanup, reviewable independently of any other design-tokens work in flight.
